Version control for people and agents

Hebra gives every coding agent its own workspace, warns when two of them touch the same file, and records who asked for each change. People review and merge. Self-host it for free or use Hebra Cloud.

02 · How it works

Many agents in one repository, without stepping on each other.

Git was built for people taking turns. Agents don't take turns. Hebra keeps them apart while they work and brings their work together under review.

1Workspaces2Claims3Conflicts4Provenance

Every agent gets its own room.

hb start makes an isolated copy of the repository with a fresh change. Agents work there. Nothing they do touches your files or each other's.

terminal
$ hb start "add OAuth login" --agent claude-code
Started workspace add-oauth-login for: add OAuth login
  change: rysttrtz   base: a6d6307d777f
$ hb start "rate limit login" --agent codex
Started workspace rate-limit-login for: rate limit login
$
terminal
$ hb status
Changes:
  M src/auth.rs
Coordination warnings:
  src/auth.rs is claimed by claude-code in add-oauth-login
  (adding OAuth)
$

Collisions show up before the merge.

Agents claim the files they are about to change. When two reach for the same one, both hear about it right away. In the CLI, over MCP and live in the hub.

A conflict never stops the loom.

A merge always finishes. Conflicts are saved inside the change and resolved when someone is ready, by a person or by another agent.

terminal
$ hb merge agents/codex/rate-limit
Merged into main.
1 conflict saved in the change:
  src/auth.rs
Work continues. Resolve it later:
$ hb resolve src/auth.rs
$
terminal
$ hb show rysttrtz
author     claude-code (agent for samuel)
task       #31 add OAuth login
session    s_9f2c41
prompt     "Add GitHub OAuth to /login"
$

Every change knows who pulled the thread.

Person, agent, task, session and prompt. Kept in history, and carried into Git as trailers when you export.

03 · Built for agents

Built for agents to drive.

Nothing in hb waits for a keypress. Agents get structured answers, their own credentials and work they can pick up and hand back.

JSON on every command

--json everywhere and stable error codes. Nothing ever waits for a keypress.

An MCP server

hb mcp exposes 32 tools, so any MCP client can drive a repository.

Mandates instead of tokens

A credential narrowed to one repo, a few operations and its own bookmarks. It expires, and revoking yours revokes it.

Tasks with leases

An agent claims a task. If it stops, the lease runs out and someone else picks it up.

Checks on your machines

Connect any computer as a runner. It pulls work over an outbound connection, so nothing is exposed. Always free.

Git in and out

Import a Git repository with its history. Export to Git deterministically, provenance included as trailers.

Agent verificationcloud

A verifier reads the change against the task's contract and reports what is missing. Capped per run.

Merge queuecloud

Approved reviews are merged together and tested once. A failing batch is split until the culprit is found.

Signed transparency logcloud

Every bookmark move is hash-chained and signed. hb verify-log catches a rewritten history, even by the server.

05 · Get started

Try it on a repo you don't mind breaking.

Install the CLI, import a project, and start two agents. It takes about a minute.

On your machine

  1. 1Install hb

    $cargo install --locked --git https://github.com/s-pl/hebra hebra-cli

  2. 2Import a project (it honours .gitignore)

    $cd my-app && hb init

  3. 3Start a workspace for an agent

    $hb start "add OAuth login" --agent claude-code

  4. 4Let your agent use it

    $claude mcp add hebra -- hb mcp

Prefer a binary? Download hb for macOS, Linux or Windows from the releases page, with checksums and signed provenance.
