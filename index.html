How it works

Many agents in one repository, without stepping on each other

Git was built for people taking turns. Agents don't take turns. Hebra keeps them apart while they work and brings their work together under review.

  1. 1

    Each agent gets its own workspace

    One command makes an isolated copy of the repository with a fresh change. Agents edit there; nothing they do touches your files or each other's.

    $ hb start "add OAuth login" --agent claude-code
    Started workspace add-oauth-login for: add OAuth login
      change: rysttrtz   base: a6d6307d777f
    $ hb start "rate limit login" --agent codex
    Started workspace rate-limit-login for: rate limit login
    $
  2. 2

    Collisions show up before the merge

    Agents claim files they are about to change. When two of them touch the same file, both are told right away, in the CLI, over MCP, and live in the hub.

    $ hb status
    Changes:
      M src/auth.rs
    Coordination warnings:
      src/auth.rs is claimed by claude-code in add-oauth-login
      (adding OAuth)
    $
  3. 3

    People review, then it lands

    Agents open a review. Checks run on your own machines, an optional verifier reads the change against the task, and a person approves the merge.

    $ hb push --bookmark agents/claude-code/oauth -r @-
    $ hb review open agents/claude-code/oauth -t "Add OAuth login"
    Opened review #12 into main
      checks: test ✓  lint ✓   approvals: 0 of 1
    $

Features

Everything a team of agents needs, and nothing that gets in their way

The core runs on your machine. The server adds collaboration: reviews, tasks, checks, and an audit trail you can verify yourself.

Workspaces per agent

hb start gives each agent an isolated working copy in milliseconds. No worktrees, no stash.

Claims and overlap warnings

Agents reserve files for a while; anyone touching them is warned before the work collides.

Conflicts never block

A merge always finishes. Conflicts are stored in the change and resolved when someone is ready.

Provenance on every change

Who made it, for whom, under which task, from which session and prompt. Kept in history and in Git exports.

Mandates instead of tokens

Hand an agent a credential narrowed to one repo, a few operations and its own bookmarks. It expires, and revoking yours revokes it.

Tasks with leases

Write tasks with acceptance criteria and dependencies. Agents claim one; if they stop, the claim runs out and someone else takes it.

Checks on your machines

Connect any computer as a runner. It pulls work over an outbound connection, so nothing is exposed. Always free.

cloud

Agent verification

A verifier agent reads the change against the task's contract and reports what is missing. Capped per run.

cloud

Merge queue

Approved reviews are merged together and tested once. A failing batch is split until the culprit is found.

Signed transparency log

Every bookmark move is hash-chained and the head is signed. hb verify-log catches a rewritten history, even by the server.

Built for agents to drive

--json on every command, stable error codes, an MCP server with 32 tools, nothing interactive.

Git in and out

Import a Git repository with its history. Export to Git deterministically, provenance included as trailers.

For agents

Agents are users, not an afterthought

Everything a person can do from the CLI, an agent can do over MCP or with --json, and every action is recorded as the agent, on behalf of the person who sent it.

  • Nothing interactive: no prompts, no pagers, no editors
  • Errors carry stable codes agents can branch on
  • Identity from the environment: HB_ACTOR, HB_TASK, HB_PROMPT
  • Claude Code is detected automatically

Compared with Git

Keep Git where it fits. Use Hebra where agents work.

Hebra imports Git history and exports back to Git, so GitHub and your CI keep working while agents work in Hebra.

GitHebra
Several agents at onceWorktrees and branches by handhb start: one workspace each
Two agents on one fileFound at merge timeWarned while they work
ConflictsStop the mergeRecorded; work continues
Who changed whatName and emailPerson, agent, task, session, prompt
Credentials for agentsYour token, all of itA narrowed, expiring mandate
Staging areaAn index to manageNone: the working copy is the change
UndoDepends on the commandEvery operation, files included
Interface for agentsParse human output--json everywhere and MCP

Get started

Try it on a repository you don't mind breaking

Install the CLI, import a project, and start two agents. It takes about a minute.

On your machine

  1. 1Install hb

    $cargo install --locked --git https://github.com/s-pl/hebra hebra-cli

  2. 2Import a project (it honours .gitignore)

    $cd my-app && hb init

  3. 3Start a workspace for an agent

    $hb start "add OAuth login" --agent claude-code

  4. 4Let your agent use it

    $claude mcp add hebra -- hb mcp

Prefer a binary? Download hb for macOS, Linux or Windows from the releases page, with checksums and signed provenance.
